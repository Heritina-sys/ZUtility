## [Unreleased]

### Added

- Full documentation set: `README.md`, `CONTRIBUTING.md`, `SECURITY.md`,
  `CODE_OF_CONDUCT.md`, this changelog.
- `docs/ARCHITECTURE.md` — platform data flow, punch-pairing state machine, and
  an explicit state-ownership table showing which state is durable and which is
  lost on restart.
- `docs/DEVICE-SDK.md` — registering `zkemkeeper`, the four SDK calls this
  service uses, verify-mode values, and COM troubleshooting.
- `.editorconfig`, issue and pull-request templates, and a CI workflow that
  builds on Windows (the only platform where the COM reference resolves).

### Removed

- `ZKUtility/bin/` and `ZKUtility/obj/` untracked — 61 build artefacts, roughly
  70% of the repository's weight, including the machine-specific
  `Interop.zkemkeeper.dll` generated by `tlbimp`.
- `.vs/` untracked — Visual Studio local state, `.suo`, design-time build
  caches, and Copilot semantic indices (`CodeChunks.db`, `SemanticSymbols.db`).
- `ZKUtility.csproj.user` and `ZKUtility.csproj.Backup.tmp` untracked.

### Known issues

Carried forward, not introduced by this release. Full list in
[README § Known limitations](README.md#known-limitations).

- **The poll loop delay is 1 millisecond** (`Task.Delay(1)`), almost certainly a
  typo for `1000`. Eight COM devices are re-polled as fast as the network allows.
- Session state and read cursors are static in-memory fields — a restart loses
  pairing context and re-pushes every device buffer from the beginning,
  duplicating history in ZKAPI.
- `POST /api/Device/sync` throws `NullReferenceException`: `DeviceController`
  declares an `HttpClient` field that its constructor never assigns.
- Pushes to ZKAPI are fire-and-forget with no retry — records are lost if the
  API is unavailable.
- Device addresses, push URL, and the dedup window are hardcoded.

## [0.1.0] — 2026-05-13

Initial import. Not tagged.

### Added

- ASP.NET Core host targeting `net10.0` with `PlatformTarget=x86`, required by
  the 32-bit `zkemkeeper` COM SDK.
- `DeviceService` — COM wrapper over `Connect_Net`, `ReadAllGLogData` and
  `SSR_GetGeneralLogData`, with guaranteed disconnection in a `finally` block.
- `AttendanceWorker` — `BackgroundService` polling eight terminals
  (`192.168.8.35`–`.42`, TCP 4370) concurrently via `Task.WhenAll`, skipping
  unreachable devices with a warning rather than failing the cycle.
- `AttendanceService` — punch-pairing state machine deriving check-in/check-out
  from punch ordering, with replay protection and a 300-second double-scan
  window, plus automatic push to ZKAPI.
- `DeviceController` — inspection endpoints for in-memory session state.

### Notes on the initial implementation

An earlier pairing strategy, preserved as commented code, keyed sessions on
fixed windows (check-in 07:00–08:00, check-out 16:00–18:00) with a 60-second
dedup. It was replaced by the ordering-based toggle, which makes no assumption
about shift hours.
